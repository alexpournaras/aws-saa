# 🪣 Amazon S3

Amazon S3 is advertised as **“infinitely scalable storage.”**

---

- 🔄 Backup & storage
- 🆘 Disaster recovery
- 🗄️ Archiving
- ☁️ Hybrid cloud storage
- 🏗️ Application hosting
- 🎥 Media hosting (videos, images, files)
- 🧠 Data lakes & big data analytics
- 📦 Software delivery
- 🌐 Static website hosting

## 🗂️ S3 Buckets

- Store **objects (files)** inside **buckets** (similar to folders/directories)
- **Bucket names must be globally unique** (across all regions & all users)
- Buckets are created at the **region level** (important!)

### 🧾 Naming Rules
- ❌ No uppercase letters
- ❌ No underscores
- 📏 Between **3–63 characters**
- ❌ Cannot be an IP address
- 🔤 Must begin with lowercase letter or number
- ⚠️ Must **NOT** start with `xn--`
- ⚠️ Must **NOT** end with `-s3alias`

---

## 📦 S3 Objects

Objects (files) are identified using a **key**, the full path:


* s3://my-bucket/`my_file.txt`
* s3://my-bucket/`my_folder/another_folder/my_file.txt`

A key consists of:
- **Prefix** → `my_folder/another_folder/`
- **Object name** → `my_file.txt`

⚠️ **Important:** Directories do *not* exist in S3. The UI console only simulates them.

### 🧱 Object Details
- Max object size: **5 TB**
- Uploads over **5 GB require Multipart Upload**
- Objects can have metadata, tags, and version IDs

#### 🔒 Accessing Private Objects
Private object URLs do not work unless accessed using a **pre-signed URL**, which includes encrypted credentials.

## 🔐 Security

### 👤 User-Based Security
IAM policies control which API calls a user can make.

### 📦 Resource-Based Security
- **Bucket Policies** → bucket-wide permissions, allow cross-account access
- **Object ACLs** → fine-grained permissions (can be disabled)
- **Bucket ACLs** → legacy, rarely used (can be disabled)

#### 🧠 Access Logic
An IAM principal can access an object if:
- IAM permissions **allow** it  
**OR**
- Resource policy **allows** it  
**AND**
- No explicit **DENY**

---

## 🔐 S3 Bucket Policies

JSON policies define access.

#### Components
- **Resources** → bucket or object ARNs
- **Effect** → Allow / Deny
- **Actions** → API calls
- **Principal** → the user or account

#### Common Uses
- Grant public access
- Force Encryption
- Grant cross-account access

#### Example Policy
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": [
        "s3:GetObject"
      ],
      "Resource": ["arn:aws:s3:::mybucket/*"]
    }
  ]
}
```

> Allow (Effect) everyone (Principal) to see objects (Action) from the S3 bucket 'mybucket' (Resource)

#### Who Gets What?
- Website users → bucket policy
- IAM users → IAM policy
- EC2 instances → IAM role with corresponding permissions
- Other AWS accounts → bucket policy with cross-account permissions

## 🛑 Block Public Access Settings

Prevents accidental exposure:
- Enabled by default
- Applies at account & bucket level
- Disable only when intentionally making data public
- These settings were created to prevent company data leaks

---

## 🕓 Versioning

- Enabled at bucket level
- When we override an object/key, it will create a new version
- Best practice for safety (unintented deletes) and rollback

#### Details
- Objects with no version will have version: `null`
- Suspending versioning does not delete previous versions
- Rollback = delete the latest version
- Deleting an object with no previous versions, creates a **delete marker**
- Removing the delete marker restores the object

---

## 🔁 Replication (CRR & SRR)

Requirements:
- Versioning enabled on both source & destination
- Replication is **asynchronous**
- Works across AWS accounts
- Requires proper IAM permissions

### Types
#### 🌍 Cross-Region Replication (CRR)
- Compliance
- Low-latency access globally
- Cross-account replication

#### 🏢 Same-Region Replication (SRR)
- Log aggregation
- Replicating between prod & test environments

### Behaviors
- Only new objects replicate
- Existing ones can be replicated using **S3 Batch Replication**
- Delete handling:
  - Delete markers can be replicated (Optional: Replication Rules -> Delete Marker Replication)
  - Deletes with version IDs **do NOT replicate** (to avoid malicious behavior)

### ⚠️ Replication Does NOT Chain
A → B and B → C does **not** imply A → C  
To replicate A → C, you must explicitly configure it as well.

## 🌡️ S3 Storage Classes

### 🛡️ Durability
- 99.999999999% durability (11 nines) across multiple AZs  
- For **10,000,000 objects**, statistically **1 object lost every 10,000 years**  
- Same durability for *all* S3 storage classes  

### 📶 Availability
- Measures how accessible the service is  
- Varies per storage class  
- Example: **99.99% availability** = ~53 minutes downtime per year  

---

## 🔄 Lifecycle Management
Automate transitions between storage classes using **Lifecycle Rules**.

Example:  
➡️ Move to **Standard-IA** after 30 days

## 🟦 S3 Standard (General Purpose)
- 99.99% availability  
- Low latency, high throughput  
- Can sustain **2** concurrent AZ failures  
- For *frequently accessed* data  

#### Use Cases
- Big data analytics  
- Mobile / gaming apps  
- Content distribution  

---

## 🟧 Infrequent Access (IA)

#### General Notes
- Lower cost than Standard, but **retrieval fees apply**  
- Designed for data accessed less frequently, but still needs fast access  

---

### S3 Standard-IA
- 99.9% availability  
- Use cases: disaster recovery, backups  

### S3 One Zone-IA
- High Durability but in **single AZ**  
- 99.5% availability  
- Use cases:
  - Secondary backup copies  
  - Data that can be **recreated** (important!)  

---

## ❄️ Glacier Storage Classes (Archival)
Low-cost storage for long-term archive and backup.

Pricing = storage cost + retrieval cost

### Glacier Instant Retrieval
- Millisecond retrieval  
- Minimum storage duration: **90 days**  
- Great for data accessed once per quarter  

### Glacier Flexible Retrieval
- Retrieval options:
  - Expedited: 1–5 minutes  
  - Standard: 3–5 hours  
  - Bulk: **Free** (5–12 hours)  
- Minimum duration: 90 days  

### Glacier Deep Archive
- Standard: 12 hours  
- Bulk: 48 hours  
- Minimum duration: **180 days**  
- Cheapest AWS storage class  

---

## 🤖 S3 Intelligent Tiering
- Small monthly monitoring + auto-tiering fee  
- Moves objects **automatically** between tiers based on usage  
- **No retrieval charges** (important!)  

---

## ⚡ S3 Express One Zone
High-performance, single-AZ storage.

- Uses **directory buckets**  
- Handles **hundreds of thousands** 100.000 of requests/sec  
- <10 ms latency  
- Up to **10× faster** and **50% cheaper** than Standard  
- 99.95% availability  

#### Use Cases
- Latency-sensitive apps (fast because it's in the same AZ)  
- Data-intensive computing  
- AI / ML training  
- Financial modeling  
- Media processing  
- High-performance computing (HPC)

#### Best Integrated With
- SageMaker  
- Athena  
- EMR  
- Glue  

---

## 🔄 Moving Between Storage Classes
Lifecycle transitions commonly follow:

➡️ Standard → IA → Glacier → Deep Archive  
📜 Moving objects can be automated using `Lifecycle Rules`

### 🟦 Transition Actions
- Move to IA after 60 days  
- Move to Glacier for archiving after 6 months  

### 🟥 Expiration Actions
- Delete access logs after 365 days  
- Delete older versions (if versioning enabled)  
- Delete incomplete multipart uploads  

### 🎯 Rule Filters
- By prefix → `s3://mybucket/mp3/*`  
- By tag → `department: finance`

## 📊 Amazon S3 Storage Class Analytics
Helps determine when to transition objects into cheaper storage classes.

- Supports Standard → Standard-IA  
- Does **NOT** support One Zone-IA or Glacier  
- Report updated daily (CSV output)  
- 24–48 hours before data begins to populate  

A great first step to designing lifecycle rules.

## 🧾 S3 Requester Pays
Default: Bucket owner pays for **storage + networking (download)**.

Requester Pays mode:
- Owner pays for **storage only**  
- Requester pays for **networking/downloads**  
- Useful for sharing large datasets with other accounts  
- Requester **must** be authenticated AWS user, so they know who to bill (cannot be anonymous)

## 📦 S3 Batch Operations

Bulk operations on **existing S3 objects** using a single request.

#### Capabilities
- Modify object metadata & properties  
- Copy objects between buckets  
- Encrypt unencrypted objects  
- Update ACLs & tags  
- Restore objects from Glacier  
- Invoke Lambda per object (custom batch actions on each object)

#### A Job Consists Of:
- A list of objects  
- The action to perform  
- Optional parameters  

#### Why Use Batch Operations Instead of custom scripts?
- Manages retries  
- Tracks progress  
- Sends completion notifications  
- Generates reports  

#### Workflow Example
Use **S3 Inventory** to generate a list of objects → query and filter with **Athena** → feed results to **S3 Batch Operations**

## 🔐 Amazon S3 — Object Encryption

### 🔸 SSE-S3 (Server-Side Encryption)
- Encryption using keys handled by AWS 
- AES-256  
- Header: `"x-amz-server-side-encryption": "AES256"`  
- Enabled by default  

---

### 🔸 SSE-KMS (Server-Side Encryption with AWS KMS)
- Keys stored & managed in AWS KMS (Key Management Service)  
- We can edit our keys, and there is audit log on key usage in CloudTrail 
- Full control over key rotation  
- Header: `"x-amz-server-side-encryption": "aws:kms"`  
- KMS decryption uses API *quotas* and that has limits!!! (we can request to increase them)  
- Includes **DSSE-KMS** (double encryption)  
- Default AWS KMS key free — custom keys cost money  

---

### 🔸 SSE-C (Server Side Encryption with Customer-Provided Keys)
- Customer provides own encryption key  
- AWS does **not** store the key  
- HTTPS required  
- CLI only (not UI console)

---

### 🔸 Client-Side Encryption
- Client encrypts before upload  
- Client decrypts after download  
- Use client-side encryption libraries (Amazon S3 Client Side Encryption Library)  

---

## 🔐 Enforce SSL/TLS (Encryption in Transit)

Force SSL/TLS Encryption in-transit with Bucket Policies by dening all HTTP calls (SecureTransport = false)

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

---

## 🔐 Enforce Encryption on Requests

Bucket policies apply **before** default encryption.

Force uploads to use SSE-KMS:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "StringNotEquals": {
          "s3:x-amz-server-side-encryption": "aws-kms"
        }
      }
    }
  ]
}
```

## 🌐 CORS — Cross-Origin Resource Sharing

Browser-based mechanism allowing requests to **other origins** (websites) while visiting a primary origin (website).

#### 🔧 How CORS Works
Scenario:
1. User visits **example.com**
2. The site loads an image from **other.com**
3. Browser sends a **preflight OPTIONS request with headers**:

```
Host: other.com
Origin: example.com
```

4. `other.com` must respond with:

```
Access-Control-Allow-Origin: example.com
Access-Control-Allow-Methods: GET, PUT
```

5. If allowed, browser proceeds with the actual **GET** request.

#### 🔑 S3 Implication
If someone needs to fetch objects from your S3 bucket:
- You must configure a **CORS policy**
- You may allow specific origins or use `"*"` to allow all origins

## 🔐 Amazon S3 — MFA Delete

#### Requirements
- Bucket **versioning must be enabled**
- Only **root account** can enable/disable MFA Delete
- MFA required to:
  - Permanently delete object versions  
  - Suspend versioning  
- Can be enabled **only via CLI**

#### Example CLI Commands
```bash
# Configure root profile
aws configure --profile root

# Enable MFA delete
aws s3api put-bucket-versioning   --bucket mfa-demo-stephane   --versioning-configuration Status=Enabled,MFADelete=Enabled   --mfa "arn:aws:iam::091232169815:mfa/lekos_a35 006370"   --profile root

# Delete object with MFA
aws s3api delete-object   --bucket lekow-demo-v2   --key beach.jpg   --version-id xSu9TLzuz1iSONMXBWbDT9joW_mF63MX   --mfa "arn:aws:iam::091232169815:mfa/lekos_a35 006370"   --profile root
```

- Logs **all access** (authorized or denied) to S3 buckets
- Used for auditing & analytics (Athena, etc.)
- Logs must go to a **different bucket** in the **same region**
- ❗ Never log into the same bucket → infinite logging loop → huge costs  
- Logs may take time to appear

## 🧊 S3 Glacier Vault Lock

Implements a **WORM** model (Write Once Read Many)

- Create a Vault Lock policy  
- Lock it permanently (cannot be edited/deleted afterward)  
- Useful for compliance & retention policies  

---

## 🛡️ S3 Object Lock (Versioning Required)

Also WORM-based. Prevents deletion/modification of object versions.

### Lock Types

#### ⏳ Retention Period
- Protect objects for a fixed time  
- Period *can be extended*  

#### 🏛️ Legal Hold
- Protects indefinitely  
- Independent of retention period  
- Requires IAM permission: `s3:PutObjectLegalHold`

#### 🔐 Retention Modes
##### **Compliance Mode**
- No one (even root) can delete or modify object versions  
- Retention period cannot be shortened  
- Retention mode itself cannot be changed  

##### **Governance Mode**
- Only specific privileged administrators can modify lock settings  
- Regular users cannot delete/overwrite protected versions

## 🔑 S3 Access Points

Simplify S3 bucket access security management.

Each access point has:
- Its own **DNS name** (internet or VPC)
- Its **own policy** (similar to bucket policy to manage security)

#### Example Use Case
- Finance team → read/write to `/finance/` directory  
- Analytics team → read-only for `/finance/` and `/sales/` directories  

#### VPC Integration
To access via VPC:
1. Create a **VPC Endpoint** (like a Gateway)
2. Allow access to bucket + access point in the **endpoint policy** (important)

#### Example Policy
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": [
        "arn:aws:s3:::my-bucket/*",
        "arn:aws:s3:us-west-2:3212:accesspoint/example-vpc/object/*"
      ]
    }
  ]
}
```

## 🧪 S3 Object Lambda

Lets you **transform objects on the fly** using Lambda before retrieved by the application.

#### How It Works
1. S3 bucket →  
2. Access Point →  
3. **Lambda function** transforms object (redact, convert, resize, watermark, etc.) →  
4. S3 Object Lambda Access Point →  
5. Application reads **modified output** from `S3 Object Lambda Access Point`

#### Use Cases
- Redacting sensitive information  
- Converting formats (XML → JSON)  
- Image resizing / watermarking  
- Data normalization for analytics
